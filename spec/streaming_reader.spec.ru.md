# Спецификация: Потоковое чтение строк (Reservoir Sampling)

## 1. Контекст и цели
В базовой версии (MVP) `stray` считывает файл целиком в память (`List<String>`). Для небольших списков (цитаты, задачи) это оправдано, однако на больших файлах (логи, словари в несколько гигабайт) это приводит к переполнению памяти (Out-Of-Memory).

Цель фичи — реализовать потоковую выборку с использованием алгоритма **Reservoir Sampling (Алгоритм R)**, гарантирующего **$O(1)$ потребление памяти** и **$O(N)$ время выполнения в один проход** при полном сохранении CLI-контракта.

---

## 2. Технический контракт и алгоритм

### 2.1. Интерфейс потокового чтения
- Реализация `StreamingLineReader` считывает файл как ленивый поток байт (`File.openRead()`), трансформируемый через `utf8.decoder` и `LineSplitter`.
- Строки анализируются «на лету» без загрузки всего файла в память.

### 2.2. Алгоритм резервуарной выборки
Для потока непустых строк с общим количеством $N$:
1. Первая валидная строка сохраняется в резервуар с вероятностью $1$.
2. Каждая $i$-я строка ($i \ge 2$) заменяет текущую строку в резервуаре с вероятностью $1 / i$.
3. По завершении потока каждая строка получает равную вероятность выбора $1 / N$.

### 2.3. Ограничения по ресурсам
- **Пиковая память (RSS):** не более 20 МБ вне зависимости от размера файла (вплоть до нескольких гигабайт).
- **Детерминизм:** при передаче фиксированного `--seed <int>` выборка на одном и том же файле воспроизводима на 100%.

---

## 3. Сценарии приемки (BDD)

### Сценарий 1: Равномерное вероятностное распределение
- **Дано:** поток из 1000 уникальных строк
- **Когда:** `stray` вызывается многократно со случайным seed
- **Тогда:** каждая строка выбирается с равномерной вероятностью $1/1000$ в пределах доверительного интервала

### Сценарий 2: Детерминированный выбор на потоке с `--seed`
- **Дано:** большой файл `large_dataset.txt`
- **Когда:** утилита вызывается `stray --seed 12345 large_dataset.txt` несколько раз подряд
- **Тогда:** каждый раз возвращается одна и та же строка

### Сценарий 3: Ограничение потребления памяти
- **Дано:** файл `huge.txt` объемом 500 МБ (миллионы строк)
- **Когда:** выполняется `stray huge.txt`
- **Тогда:** выполнение завершается успешно с кодом `0`
- **И:** потребление памяти (RSS) не превышает 20 МБ

### Сценарий 4: Поток содержит только пустые строки
- **Дано:** поток, состоящий исключительно из символов переноса строки и пробелов
- **Когда:** чтение завершается
- **Тогда:** код завершения `1`
- **И:** `stderr` содержит `Error: File is empty`
